## v2.4.2

**当前版本** ｜ 程序内版本号 `LM_VERSION = 2.4.2`

一个基于原生 PHP + MySQL 的轻量博客系统，不依赖任何框架，自带可视化安装向导。

### 功能

- **内容管理** —— 文章支持 Markdown / HTML 双模式，带封面、摘要、标签、分类、置顶、草稿、图集；评论支持楼中楼回复、审核机制、敏感词过滤；标签云、分类归档、时间轴归档、RSS 订阅
- **用户与社交** —— 用户注册（需审核）/ 登录 / 资料编辑 / 头像上传；友情链接与友链自助申请；GitHub / Gitee / GitCode 三平台 OAuth 登录；基于 GitHub 仓库的相册图床（自动转 jsDelivr CDN）
- **工具与增强** —— AI 文章摘要（兼容 OpenAI / 自定义接口，多 Provider）；服务状态监控（TCP/HTTP 探测、定时任务、历史日志）；天气挂件、一言、音乐播放器；工具页（蓝奏云解析等）；小游戏模块；赞助 / 捐赠页
- **安全与性能** —— CSRF 令牌、XSS 过滤、SQL 预处理、上传图片重处理；通用限流、登录失败锁定、登录日志；AES-256-CBC 加密存储 API Key；静态资源长缓存与分级 CDN 缓存策略（Cloudflare 友好）；粒子 / 星空背景、深色模式、响应式布局

## 仓库归档方式说明

本项目源码统一归档在 `src/` 目录下，**每个版本一个完整文件夹**，历史版本也保留在其中，可自行选择。

之所以按版本号保留完整快照，是因为本站采用「整包上传」的部署方式：

- 任意历史版本都能直接重新下载部署，不必回滚 Git 历史
- 用户可以明确知道自己装的是哪个版本
- 多版本可以并存，便于对照排查

代价是仓库体积会随版本数增长，因此旧版本停止维护后可移入 `archive/` 或删除。

## 新增版本的流程

1. 复制上一版本目录：`cp -r src/<上一版本> src/<新版本>`
2. 修改 `src/<新版本>/includes/config.php` 中的 `LM_VERSION`
3. 新增或更新 `src/<新版本>/README.md`
4. 更新 `src/README.md` 的版本列表
5. 在本文件顶部追加新版本段落
6. 如有数据库变更，在 `docs/migrations/` 添加 SQL 脚本
7. 打 tag 并创建 Release，附上该版本的 zip 源码包
