# 修复记录（2026-09-16）

本轮针对代码审查发现的缺陷做统一修复，未新增功能、未改动数据库结构。
所有 PHP 文件通过 `php -l`，JS 文件通过 `node --check`，关键逻辑已实测。

---

## 一、缺陷修复（有功能/数据影响）

### 1. 后台「批量操作」会误删文章（严重）

`admin/articles.php` 的批量表单曾包住整张表格，而每行「删除」按钮自己又是 `<form>`，
表单嵌套会被 HTML 解析器丢弃内层起始标签：行内的 `action=delete` 与 `ids[]` 并入外层表单，
点「批量发布」实际提交的是 `action=delete`，且只带第一行的 ID —— 会删掉当前页第一篇。

- `admin/articles.php`：批量表单改为独立空表单，勾选框用 `form="batch-form"` 关联；顺带给全选/行选择框补 `aria-label`。
- 验证：用标准 HTML5 解析器（parse5）复刻修复前后结构对比，修复后批量提交为 `action=publish & ids=[勾选项]`，单行删除只提交自身 ID。

### 2. 暗色模式配色错乱

`style.css` 里旧粉色主题的 `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`
特异度高于新主题的 `[data-theme="dark"]`，导致「跟随系统 + 系统深色」时出现一半深一半浅的混合态；
「系统深色 + 手动选深色」时新主题深色配色永远不生效。

- `assets/css/style.css`：移除该媒体查询（保留原地的说明注释）。
- `template/header.php`、`admin/template/header.php`、`login.php`、`assets/js/main.js`：
  「跟随系统」由 JS 解析成显式的 `data-theme="dark|light"`（三处内联初始化脚本 + `applyTheme()` 一致处理）。
- `assets/css/theme-refresh.css`：补齐新主题未覆盖的遗留深色令牌（`--secondary-color`、`--gradient-card`、`--code-color`、`--shadow`）。

### 3. 后台「统计代码」设置不生效

`site_analytics` 只在保存时校验，前台模板从未输出。

- `template/sidebar.php`：在所有前台页脚输出该代码，输出前再次用 `isValidAnalyticsCode()` 校验（防备份还原等旁路写入的旧数据）。
- 验证：实测校验器对合法外链脚本放行、对内联脚本/非白名单域名/内联事件处理器拒绝。

### 4. 后台「维护模式」开关不生效

`site_maintenance` 存了不用，前台没有任何拦截。

- `includes/functions.php`：新增 `app_maintenance_guard()` 与 `app_render_maintenance_page()`，
  并在 `app_session_start()` 末尾调用（所有前台页面都经过它；后台页面用原生 `session_start()`，天然豁免）。
- 行为：访客访问前台返回 `503 + Retry-After: 3600` 的自包含维护页；管理员（已登录）放行以便关闭维护；
  `/admin/`、`/api/`、`/assets/`、`/cache/`、登录/注册/资料页放行。
- 验证：8 个场景实测（访客/管理员/普通用户 × 首页/后台/API/登录页/关闭状态），全部符合预期，响应头为 `Status: 503`、`Retry-After: 3600`、`Cache-Control: no-store`。

### 5. 天气组件兜底必然失败

`assets/js/weather-widget.js` 回退请求 `https://wttr.in`，但该域不在 CSP `connect-src` 中，兜底会被静默拦截。

- `includes/Security.php`：`connect-src` 放行 `https://wttr.in`。

### 6. 前台访客无法回复评论（楼中楼缺失）

`parent_id` 的后端校验与两级渲染一直存在，但前台没有回复入口，访客只能发顶级评论。

- `article.php`：评论表单新增隐藏 `parent_id` 与「正在回复 X / 取消回复」提示条；每条评论与回复后新增「回复」按钮
  （回复「回复」时归入所在楼层并自动补 `@昵称`）。
- `assets/js/ui-enhancements.js`：新增 `initCommentReply()` 负责写入父评论 ID、滚动定位与取消还原。
- `assets/css/theme-refresh.css`：新增回复按钮与提示条样式。

### 7. 主题切换动画覆盖了其它动画

`initThemeTransition()` 在页面加载时就给 `.header/.card/.article-item` 等写内联 `transition`，
把样式表里的 `transform`/`opacity` 过渡一并覆盖 —— 智能头部收起、列表滚动渐入实际失效。

- `assets/js/main.js`：改为切换主题的瞬间临时加 `.theme-transitioning` 类，`onload` 不再写任何内联过渡。
- `assets/css/theme-refresh.css`：新增该类下的颜色过渡规则（含 `prefers-reduced-motion` 关闭分支）。

## 四、缓存失效补齐

此前只有文章增删改会清空页面缓存，改设置、审核评论、发说说、改友链都要等 TTL（默认 300 秒）过期。

- `includes/functions.php`：新增 `app_purge_page_cache()`。
- 接入点：`admin/settings.php`、`admin/comments.php`、`admin/shuoshuo.php`、`admin/links.php`、
  `admin/link-apply.php`、`admin/categories.php`、`admin/sponsors.php`、`admin/donors.php`（操作成功后），
  以及前台 `article.php`、`guestbook.php`（评论/留言直接通过审核时）。
- 验证：实测调用后缓存文件被清空，`index.html`（防列目录）保留。
