# 版本索引 · Versions

本目录按**版本号**归档林梦博客的完整可部署源码。每个子目录都是一个独立、自包含的站点版本，可以单独下载、单独上传到服务器运行。

## 📦 版本列表

| 版本 | 目录 | 状态 | 程序内版本号 | 说明 |
|------|------|------|--------------|------|
| v2.4.2 | [`v2.4.2/`](v2.4.2/) | ✅ 当前推荐 | `LM_VERSION = 2.4.2` | 最新稳定版，功能完整 |

> 「程序内版本号」指 `includes/config.php` 中的 `LM_VERSION` 常量，它是程序自己运行时报出的版本，与目录名保持一致。

## 🚀 我该用哪个版本？

**普通用户直接用最新版**，也就是 `v2.4.2/`：

```
src/v2.4.2/   ←  把「这个文件夹里面的全部内容」上传到网站根目录
```

详细部署步骤见根目录 [README](../README.md)。

## 📁 目录约定

```
src/
├── README.md          # 本文件：版本索引
└── v2.4.2/            # 版本目录，名称即版本号
    ├── README.md      # 该版本的详细说明
    ├── index.php      # 站点入口
    ├── includes/      # 核心库
    ├── admin/         # 后台
    ├── api/           # 接口
    ├── assets/        # 静态资源
    ├── setup/         # 安装向导（安装后需删除）
    └── ...
```

每个版本目录内部的结构，就是**该版本原样的站点根目录结构**——直接整体上传即可，不需要再调整层级。

## ➕ 新增版本

发布新版本时：

1. 复制上一版本目录为新版本号目录，例如 `cp -r v2.4.2 v2.5.0`
2. 修改 `v2.5.0/includes/config.php` 中的 `LM_VERSION` 常量
3. 在 `v2.5.0/README.md` 写明本版本的变更与注意事项
4. 更新本文件顶部的版本列表表格
5. 在 `docs/CHANGELOG.md` 追加变更记录
6. 打 tag 并创建 Release：`v2.5.0`

> **为什么每个版本存一份完整代码快照？**
> 因为本站是「整包上传」的部署方式。保留完整快照，任何历史版本都能随时重新部署，不必回滚 Git 历史。代价是仓库体积随版本数增长，因此**旧版本在停止维护后可移入 `archive/` 或删除**。
